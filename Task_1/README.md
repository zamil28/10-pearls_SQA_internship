## 📋 Project Overview

This repository contains the requirement analysis documentation for an **Online Book Store** system, developed as part of a QA internship assignment. The purpose of this project is to demonstrate the ability to analyze product requirements and translate business needs into structured QA documentation, including functional requirements, non-functional requirements, user stories, and acceptance criteria.

## 🎯 Learning Objectives

- Understanding requirement analysis for an e-commerce platform
- Identifying functional requirements
- Identifying non-functional requirements
- Writing user stories in structured format
- Writing acceptance criteria using Gherkin syntax
- Translating business requirements into testable scenarios
- Demonstrating clear and organized documentation practices

## 📖 Report Structure

The report is organized into the following sections:

1. **Requirement Understanding** — business goal, expected platform behavior, key workflows, and key actors
2. **Functional Requirements** — 10 functional requirements (minimum 5 required)
3. **Non-Functional Requirements** — 5 non-functional requirements (minimum 2 required)
4. **User Stories** — 10 user stories in the format *As a … I want … so that …*
5. **Acceptance Criteria** — 7 scenarios written in Gherkin syntax (`Given … When … Then …`), minimum 5 required
6. **Summary** — recap of all deliverables against assignment requirements

## 🛠️ Tools & Techniques Used

- **Gherkin syntax** for acceptance criteria
- **Requirement analysis techniques** (functional/non-functional decomposition, user story mapping)
